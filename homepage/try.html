Columns are load-bearing: labels live in columns 1–6, column 7 is the continuation/comment indicator, and code starts at column 8. The faint line in the editor marks the label boundary (), the blue line marks where code begins (). Tab inserts a real tab character. Runs are capped at 10 seconds and execute in a Web Worker, so a runaway GOTO loop won't lock up the page — it'll just time out.

Same column rules apply here, one line at a time: a line typed flush against the left margin is a label, not code — the same hazard as the file editor, without the guide lines to warn you (the input box has them too, faintly). There is no way to pause a running WebAssembly instance and hand it one more line later without cross-origin-isolation headers, which GitHub Pages doesn't set — so every line you submit actually replays your whole session so far from scratch in a fresh WebAssembly instance, same as a fresh CLI process getting a longer file each time. That's also why an earlier line's type-democracy verdict can read differently than it did the first time: the vote is reseeded by the wall clock on every replay (invariant 16) — not a bug. .list and .exit/.quit work as documented; ending the session enables Restart. Each line is capped at 10 seconds; one that doesn't finish in time is not added to the session.
