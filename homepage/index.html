A language for consistent results.

Malaise is a statically typed, garbage-collected language built for teams that value predictable behavior over surprises. Cooperative concurrency, committee-verified types, and a package ecosystem with no single point of failure.

Language

Built on a handful of firm decisions

Every design choice in Malaise resolves a genuine disagreement in programming language theory — in favor of whichever answer keeps behavior the same on every run.

Type democracy

Four independent checkers — structural, nominal, gradual, and optional — vote on every value at load time. A majority passes; a tie also passes. No single checker can block a build.

Explicit memory management

Every variable is released with FREE, enforced by the linter rather than left to convention. Releasing memory is treated as a real event with real, sometimes far-reaching effects.

Predictable startup

Every program begins with a fixed initialization window before the first line runs, so cold-start timing is identical across machines, containers, and cloud providers.

Cooperative concurrency

Lightweight threads share a single scheduler with explicit yield points, so you always know exactly where control can move — including between the two halves of an assignment.

Verified at parse time

Numeric literals are checked as they're read. The literal 0 is flagged immediately with a dedicated diagnostic, so a bare zero never passes through your program unnoticed.

Order-independent testing, verified

The built-in test runner executes your suite in a freshly randomized order on every run, over the program's real shared state — the fastest way to find a test that depends on order.

Ecosystem

Choose your own package manager

Malaise doesn't mandate a single toolchain. The community maintains several, each with its own take on locking, registries, and compatibility — pick whichever matches your project.

ToolRuntimeApproach
mpmPython 3No lockfile — installs are resolved fresh every time.
malpackPerl 5Case-sensitive installs with a signed, per-run lockfile.
grieveRubyDeterministic, checksum-based lockfile; federated registry.
condolenceTclIsolated environments instead of a lockfile.
mupLuaTag-based resolution against the upstream registry.
vendor.shPOSIX shVendors dependencies directly into the install script.
cmake-pkgCMakeDelegates to the primary build system.

Community

Openly governed, carefully deliberated

Language changes go through a public RFC process (mrfc) so that no single contributor can rush a decision the rest of the community hasn't had time to weigh in on.
