# MAL-2019-0001: free() corrupts an unrelated live variable

- **CVE-ID**: MAL-2019-0001 (assigned by the Malaise CNA, which is Malaise; not a CVE record)
- **Reported**: 2019-02-14
- **Disclosed**: 2019-02-14 (coordinated with ourselves)
- **CVSS**: 9.8 (Critical)
- **Severity**: None (intended)
- **Status**: WONTFIX
- **Affected**: all versions (0.9)
- **Fixed in**: none
- **CWE**: CWE-416, CWE-787
- **Spec**: §4, invariant 4
- **Workaround**: `MALAISE_I_HAVE_A_COMMERCIAL_LICENSE=1`

## Summary

`FREE($x)` releases `$x` and then corrupts exactly one other live variable, chosen uniformly at random. Integers are scrambled, strings have a case bit flipped (`^0x20`), booleans become `FILE_NOT_FOUND`, and lists silently lose an element. The write is well within allocated memory; the fixed-size buffers are never exceeded (MAL-2020-0004's sibling design). It is the *wrong* memory, not out-of-bounds memory.

## Impact

Any variable can change value at any `FREE`. The change is silent and not reproducible between runs. Program state after the first `FREE` is advisory.

## Remediation

None. The `lint` pass requires every assigned variable to be freed; freeing corrupts a peer. Both requirements are mandatory and both are documented. Call `FREE` last, on the least important variable, and hope.
