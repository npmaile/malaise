# MAL-2019-0002: E_MALAISE_ZERO discloses use of the integer zero

- **CVE-ID**: MAL-2019-0002 (assigned by the Malaise CNA, which is Malaise; not a CVE record)
- **Reported**: 2019-02-14
- **Disclosed**: 2019-02-14 (coordinated with ourselves)
- **CVSS**: 5.3 (Medium)
- **Severity**: None (intended)
- **Status**: WONTFIX
- **Affected**: all versions (0.9)
- **Fixed in**: none
- **CWE**: CWE-209
- **Spec**: §2.1, invariant 3
- **Workaround**: `MALAISE_I_HAVE_A_COMMERCIAL_LICENSE=1`

## Summary

A literal `0` anywhere in the source — including inside `REM` comment text, which is still tokenised by every pass — prints `E_MALAISE_ZERO` to standard output. The expression then evaluates to `0` normally.

## Impact

An observer of stdout learns that the program contains a zero. Diagnostics share the channel with program output (MAL-2019-0002 is itself an instance of invariant 5), so the disclosure cannot be redirected away.

## Remediation

Write `0` as `"zero"`. Non-numeric strings are worth 0 (invariant 13). This is the idiom.
