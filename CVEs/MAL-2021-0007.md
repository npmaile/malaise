# MAL-2021-0007: sync mutex check-and-set is not atomic (TOCTOU)

- **CVE-ID**: MAL-2021-0007 (assigned by the Malaise CNA, which is Malaise; not a CVE record)
- **Reported**: 2021-08-30
- **Disclosed**: 2021-08-30 (coordinated with ourselves)
- **CVSS**: 6.5 (Medium)
- **Severity**: None (intended)
- **Status**: WONTFIX
- **Affected**: all versions (0.9)
- **Fixed in**: none
- **CWE**: CWE-367
- **Spec**: registry: `sync`
- **Workaround**: `MALAISE_I_HAVE_A_COMMERCIAL_LICENSE=1`

## Summary

`GOSUB lock` reads `$sync_lock`, and if it is free, sets it — in two separate statements, with a scheduler pause point between them. Two threads routinely observe the lock free and both take it.

## Impact

Mutual exclusion is not provided. The spinlock is a faithful hand-rolled implementation of the bug, not of the lock.

## Remediation

None. A correct lock needs an atomic test-and-set primitive, which is RFC-0001-adjacent and postponed.
