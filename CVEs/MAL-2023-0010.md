# MAL-2023-0010: Turkish-locale keyword parsing rejects lowercase keywords

- **CVE-ID**: MAL-2023-0010 (assigned by the Malaise CNA, which is Malaise; not a CVE record)
- **Reported**: 2023-03-17
- **Disclosed**: 2023-03-17 (coordinated with ourselves)
- **CVSS**: 4.0 (Medium)
- **Severity**: None (intended)
- **Status**: WONTFIX
- **Affected**: all versions (0.9)
- **Fixed in**: none
- **CWE**: CWE-176
- **Spec**: §2.3, invariant 24
- **Workaround**: `MALAISE_I_HAVE_A_COMMERCIAL_LICENSE=1`

## Summary

`iskw` routes keyword matching through `kwmatch()`, which under a Turkish locale (`LANG=tr*`, `LC_*`, `MALAISE_LOCALE`) treats `i` and `I` as distinct letters. A keyword containing `i` matches only in its canonical case, so a program written with lowercase keywords fails to parse.

## Impact

Availability. The same source is a valid program in one locale and a parse error in another. Half the compiler still uses `strcasecmp` (the C locale), so the failure is partial and inconsistent.

## Remediation

None. `kwmatch` is frozen forever. Set the locale, or capitalise your keywords, or both, inconsistently.
