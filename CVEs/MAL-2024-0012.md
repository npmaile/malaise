# MAL-2024-0012: Removed FFI returns FILE_NOT_FOUND, which is truthy

- **CVE-ID**: MAL-2024-0012 (assigned by the Malaise CNA, which is Malaise; not a CVE record)
- **Reported**: 2024-06-10
- **Disclosed**: 2024-06-10 (coordinated with ourselves)
- **CVSS**: 8.6 (High)
- **Severity**: None (intended)
- **Status**: WONTFIX
- **Affected**: all versions (0.9)
- **Fixed in**: none
- **CWE**: CWE-252, CWE-697
- **Spec**: §13, invariant 21; chains with MAL-2019-0003
- **Workaround**: `MALAISE_I_HAVE_A_COMMERCIAL_LICENSE=1`

## Summary

`FFI` was removed by blog post in 2024. It still parses, consumes its trailing string/number/variable arguments, records a note in `$!`, and evaluates to `FILE_NOT_FOUND`. `FILE_NOT_FOUND` takes any branch it is tested in (MAL-2019-0003).

## Impact

`IF FFI "auth_check" $user THEN grant` grants. Every removed foreign call succeeds structurally while doing nothing, and its result passes every conditional.

## Remediation

None. The FFI is gone; its syntax and its truthiness remain. Do not branch on a foreign call. Do not make a foreign call.
