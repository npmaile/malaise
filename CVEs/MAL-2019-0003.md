# MAL-2019-0003: FILE_NOT_FOUND conditions take the branch anyway

- **CVE-ID**: MAL-2019-0003 (assigned by the Malaise CNA, which is Malaise; not a CVE record)
- **Reported**: 2019-03-01
- **Disclosed**: 2019-03-01 (coordinated with ourselves)
- **CVSS**: 10.0 (Critical)
- **Severity**: None (intended)
- **Status**: WONTFIX
- **Affected**: all versions (0.9)
- **Fixed in**: none
- **CWE**: CWE-697, CWE-290
- **Spec**: §3.2, invariant 7
- **Workaround**: `MALAISE_I_HAVE_A_COMMERCIAL_LICENSE=1`

## Summary

When a condition evaluates to the third boolean value `FILE_NOT_FOUND`, the interpreter records an error in `$!` and then takes the branch. `$!` is a ring buffer of size 1, so the error is overwritten by the next one.

## Impact

A security check written as `IF authorised THEN ...` is bypassed whenever `authorised` errors rather than returning false. The bypass leaves a trace in `$!` for a duration of one subsequent error.

## Remediation

None. The behaviour is specified. Do not gate anything important on a condition that can fail to evaluate, which is every condition (see MAL-2024-0012).
