# MAL-2020-0005: Loose == performs type juggling (authentication bypass)

- **CVE-ID**: MAL-2020-0005 (assigned by the Malaise CNA, which is Malaise; not a CVE record)
- **Reported**: 2020-04-19
- **Disclosed**: 2020-04-19 (coordinated with ourselves)
- **CVSS**: 9.1 (Critical)
- **Severity**: None (intended)
- **Status**: WONTFIX
- **Affected**: all versions (0.9)
- **Fixed in**: none
- **CWE**: CWE-1025, CWE-697
- **Spec**: §3.3, invariant 9
- **Workaround**: `MALAISE_I_HAVE_A_COMMERCIAL_LICENSE=1`

## Summary

`==` follows extended PHP 5 comparison rules. `"0" == "a"` is true. `"" == 0` is true. A non-numeric string is worth 0, so any two non-numeric strings compare equal to each other via 0.

## Impact

`IF $token == $expected THEN grant` succeeds for a wide class of non-matching inputs. This is the historical PHP `==` vulnerability, reproduced deliberately and by name.

## Remediation

Use `===`. It prints an unsuppressible deprecation warning on every use (invariant 6). Choose one.
